# Maintenance production impact v1 — locked protocol

## Material Passport
- ARS academic-research-suite / experiment-agent, run; planned 2026-10-04.
- Protocol `maintenance_production_impact_v1`; additive module; previous simulators/results unchanged.
- Research question: does scarce heterogeneous technician capacity cause sustained production delay, and can a simple coordinated calendar recover it versus a risk-aware health baseline?

## Model and intervention
Six machines, fixed machine-specific production streams, all jobs available at t=0. Each job needs an integer number of productive ticks on its assigned machine; no rerouting or job ordering decision. Preempt/resume production at tick boundaries for maintenance/failure, no lost work. This is a parallel fixed-route diagnostic, NOT a full flexible job shop or real plant validation.
Tick order: eligible maintenance requests -> FIFO dispatch -> service or production/failure downtime -> complete service/reset. A queued healthy machine continues production and aging; failed machines stop production; service pauses aging and production. On a productive tick completing the final job, do not draw a subsequent failure for a machine with no remaining workload. Completed machines submit no new requests and stop aging; existing queued/service commitments remain immutable until dispatched/completed (possibly still outstanding at production finish). Stop as soon as all production jobs finish. Makespan excludes post-production outstanding maintenance; report outstanding work, maintenance cost and downtime separately, no terminal cost optimization.
Wear uses productive ticks (not idle wall time), failure_age sampled [12,16,20], probability [.25,.4,.6]. Service durations fast=2, slow=6, uniform=4; high-pressure K=2, low K=6. Alternating specialty repeats in low K, preserving each row mean 4 in all cells. Each machine prefers specialty0 with probability .75, otherwise1; these choices and initial ages sampled once per instance, held across all cells. Initial ages uniform in 0..failure_age//2; no selection for synchronized states. All technicians eligible; nonpreemptive maintenance. New requests use the same public failed-first / earliest safe-start / machine-ID admission order for every policy; existing FIFO queues cannot be reordered. This matches the assignment planner's assumed admission order.
Short/long workload 16/64 jobs per machine. One 64-job stream per machine generated from instance seed, durations uniform integers2..6; short is its exact prefix. Same workload, wear, ages and common failure uniform per (shock seed, wall tick, physical machine) across policies/cells/lengths. Each cell changes only capacity and service matrix. Ideal no-maintenance/no-failure makespan = max machine stream duration, a reference bound, not an executable competitor.

## Frozen policies and development
I_individual_fast: individually health-triggered, enqueue to shortest-service worker ignoring backlog. Diagnostic weak baseline only, never used for primary success.
H_health_risk_dispatch: same health triggers, jointly processed in failed-first / earliest safe-start / machine-ID order. For each triggered machine select worker minimizing duration + waiting + expected extra repair/failure-time exposure for predicted backlog, tie shorter backlog then duration then worker ID. Backlog includes assignments made earlier in the same decision. No future shock access. Threshold offset grid [0,1,2,4]. I shares the selected H offset, not separately optimized.
S_capacity_reservation: failed-first / earliest safe-start / machine-ID ordering; immutable current backlogs. For each machine find latest nonoverlapping technician slot within [due-lead,due], or earliest available from max(0,due-lead). Score duration + early/failure_age*mean(service row) + waiting + failure-risk proxy; tie latest start, then worker ID. Emit only start-now requests; rebuild reservations each tick. Healthy candidates whose remaining production fits within due submit no request. Lead grid [0,2,4,6]. This is an analytical ranking heuristic, not exact optimality.
Both H and S know current health, durations, full remaining production, hazard parameters; neither sees realized future shocks. H avoids unnecessary maintenance if remaining productive ticks fit before hazard. H assignment uses risk to resolve completion ties; old B comparator not reused. Neither policy is tuned on the other's evaluation performance.
No training or neural checkpoint. Tune H offset and S lead separately on mean episode makespan/ideal makespan, equally weighted across development instances/cells/lengths. One global offset and one global lead, ties smaller parameter, not per test cell. Save/reload policy.json before evaluation.

## Metrics and predeclared gates
Primary cell high/heterogeneous/long64. Primary recovery: mean instance-relative (H-S)/H makespan >=5% AND paired absolute H-S CI95 lower>0. Report confidence interval for relative recovery separately; undefined ratios fail.
Resource-specific burden: for H long64, per-instance `(HH-HU)-(LH-LU)` in makespan/ideal units; paired CI95 lower>0. This separates heterogeneity/capacity interaction from their standalone effects, with matched service row means. Also report H high-low within skills; a failed interaction does not prove no scarcity impact.
Persistence diagnostic: primary relative recovery long >= .5*max(short relative recovery,0) AND H mean late waiting machine-ticks>0. Late = wall tick >= floor(ideal makespan/2), fixed by workload rather than realized policy outcome. This is an operational diagnostic, not a separate corrected significance test; does not prove steady-state optimality.
`problem_support` = recovery AND resource_specific_burden AND persistence. Report every gate separately. Failure can mean inadequate heuristic, insufficient panel, or absent practical effect; it does not establish the problem is impossible/irrelevant. No gate requires S to beat weak I alone. Scientific gates false on smoke.
Secondary: makespan, normalized makespan, per-instance relative recovery, job completion tardiness-free times (no due-date metric), failures, queue/late queue machine-ticks, service/failed downtime, productive ticks, late production ticks, maintenance count/cost, final jobs and work balance, outstanding work, runtime. Job makespan measured directly from completion logs, not operating proxy. Per-job completions are diagnostics, not independent inference units.
