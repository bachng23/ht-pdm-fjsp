## D algorithm and comparator settings
At each tick project busy remaining+committed FIFO workload per technician with current observed PM/CM durations. Sort free eligible machines failed-first then deadline then physicalID. Forward append one hypothetical service per machine: earliest start=max(worker available, max(0,deadline-lead)). Choose worker lexicographically by start lateness, finish time, start time, duration, workerID. This EDF forward list scheduling is a heuristic: greedy worker choices are not an optimal feasibility oracle.
For each worker, shift its entire new sequence right by max(0,min(deadline-start)) computed before shift; keep order/gaps and preserve committed backlog. A late item prevents right shifting that chain. Emit only planned services starting at0 on an actually idle worker with no FIFO commitment. All future slots replanned next tick, no reservation commitments. No new D queues, no cancellation, no automatic repair of completed/occupied targets. Record plan starts/durations/deadlines/releases and lateness; overlapping or illegal emitted actions fail audit. Plan feasibility is conditional on this single hypothetical maintenance round and current durations, not all future maintenance cycles.
