## Research question and hypothesis
Can a simple backward-reservation maintenance heuristic E match cost-aware joint lookahead C within a 5% cost margin while improving over strong health/queue baseline B? What planned-downtime/operating-time trade-off accompanies the gain? Primary cell is high pressure/heterogeneous, planned downtime price 1, horizon 24 (fixed before outcomes). Primary E cost noninferiority gate: upper percentile CI95% of instance-relative `(E-C)/C` <= .05, all C means >0; undefined ratios are explicit and fail the gate. Comparator validity: B-C cost saving CI lower >0. Useful simple baseline additionally requires B-E saving >=5% (mean paired instance-relative) and absolute-saving CI lower >0, with all B means >0. Operational guard additionally requires lower CI95% of E-B operating-time proxy gap >= -.02 (2 percentage points). Report gates separately; cost noninferiority is not equality/optimality. Null or failed gates remain valid results, not grounds to change panel or margins.

## Algorithms and frozen semantics
Reuse Config/State/transition/closeout/common shock functions at base 07697c2; do not change old modules/results. Two machines; high pressure K=2, low K=4. Matched row-mean service times, either uniform or heterogeneous same/complementary specialty. All eligible. Existing FIFO queues immutable, service nonpreemptive, machine ages while queued and stops aging/operating during service, resets at completion. No job-shop, prognostics noise or technician travel.

B: original health-triggered globally completion-time-aware assignment, threshold offset re-selected on NEW development data separately for each downtime-price family. C: unchanged depth-3 joint exact expectation with tail-2 following that B and same terminal liability; same state/dynamics as B/E, no future realized shocks. No learning/training checkpoints.

E: analytical calendar heuristic, no branching/rollout/oracle. Derive latest safe start `due=max(0,failure_age-age-1)` for each currently free machine; failed machines due now. Build technician calendars from remaining service plus immutable queued jobs. Order candidate machines by failed first, then due, then public physical-machine order. For each machine/technician find latest nonoverlapping start in `[max(0,due-lead),due]`; if none, earliest nonoverlapping start from that lower bound. Choose slot minimizing service duration*planned price + maintenance cost*earliness/failure_age + waiting price*lateness + delay-risk penalty. For healthy machines late risk is `1-(1-p)^lateness`, multiplied by failure penalty+failed downtime price; failed machines instead pay predicted failed-downtime delay. This is a disclosed ranking heuristic, NOT exact expected total cost. Tie by latest start then technician. Reserve the slot in the temporary calendar, emit request ONLY when slot starts now; future reservations rebuilt each step. Existing jobs are not moved/cancelled. Jobs starting service are safe before hazard, per original semantics; due is a safe-start deadline, not completion deadline.

E lead grid 0,1,2,3,4. Choose one lead per downtime-price family on development mean cost per step, averaged equally over instances/cells/horizons; ties smaller lead. B offset grid 0,1,2, chosen independently to minimize B development cost per step per price. Tune neither on C performance nor sealed outcomes. C depth/tail fixed. E reservation uses the known hazard probability in its simple score, not future shocks. All receive complete current state, price and duration matrix; no oracle supervision.
