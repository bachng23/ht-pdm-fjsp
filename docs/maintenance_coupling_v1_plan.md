## Question and falsifiable hypothesis
Does jointly choosing maintenance request timing and technician assignment reduce expected system cost beyond health-triggered, globally queue-aware assignment? Hypothesis: C beats B by at least 5% in the high-pressure/heterogeneous cell, with positive instance-level paired bootstrap lower confidence bound for absolute savings. Interaction (heterogeneity effect on C–B savings under high versus low pressure) must also have positive lower bound to support the stronger coupling-specific claim. Failure rejects this gate, not proof of equivalence. A–B is secondary and separates assignment improvements.

## Frozen model and policies
New standalone simulator; existing environments/results unchanged. Two machines, finite horizon 12. Low pressure has four technicians (two copies of each skill profile); high pressure has two technicians (one copy). This is capacity relative to fixed demand, not different failure laws. All technicians eligible; skill affects service time only. Homogeneous service = fast+1; heterogeneous fast/slow = fast/fast+2, rows either complementary or shared preference. Row-average duration is identical across skills AND capacity cells. Requesting a busy technician is valid; one immutable FIFO queue per technician; simultaneous requests follow public physical-machine order. Queued machines operate, age and can fail. Service is nonpreemptive; entire duration is down and aging/failure suppressed. Recovery/reset at completion. Failed idle/queued machines accrue failed downtime, servicing machines accrue planned downtime. No prediction noise or production job-shop in this initial mechanism test.

A: health threshold then individually fastest technician, ignoring congestion. B: SAME threshold and triggering machines, but enumerate their assignments and minimize sum of predicted completion times accounting for current busy work and FIFO backlog. C: enumerate feasible joint defer/request actions; exact expected cost for 3 decision steps, then 2 steps following B, then the same closeout liability. Execute only first action, replan. This is finite-budget model-based planning, not new RL architecture and not guaranteed global optimality. All receive the SAME complete current state, costs, durations and known hazard. None receive future shocks. A/B threshold chosen ONCE on development panel; candidates threshold offset 0,1,2 from failure age; minimize B cost, same offset A/B, frozen before full/sealed evaluation. C depth=3/tail=2 never tuned. No train seeds/training checkpoints because there is no learning.

Objective: undiscounted maintenance + planned downtime + failed downtime + new-failure penalty + queue waiting + terminal liabilities. Terminal liabilities pay remaining service downtime, queued maintenance/service and FIFO waiting, plus one failure penalty for failed unqueued/unserved machines. This finite-horizon closeout is explicitly an accounting convention, not proof of long-run production economics. All policies and oracle use it identically. Primary inference uses total including closeout; also report stage cost and terminal share separately.

Exact stochastic finite-horizon oracle: separate horizon-4 panel of first TWO sealed instances, all four cells; optimize all feasible actions with the same closeout. Report A/B/C exact expected costs and gaps at that SAME horizon, separately from horizon-12 rollout performance. No oracle values are used for policy tuning. Tiny oracle tests compare with independent un-memoized action-tree recursion, including fractional hazard, plus deterministic scripted timeline tests. Permutation audit preserves physical-machine tie order and shock identity; do not assert label invariance while changing simultaneous FIFO order.
